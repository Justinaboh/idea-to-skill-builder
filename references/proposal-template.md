# Proposal Template (Stage 6)

Present these sections in order. Keep language plain. Tag each notable item **Original**, **Researched** (with source), **Designed**, or **Assumed**.

## A. Proposed identity
- Skill name (lowercase, hyphenated, matches the folder)
- One-sentence description
- Main purpose and the problem it solves
- Intended users

## B. What the skill will do
Concrete capabilities. State what a person can accomplish. Reject vague claims such as "improves productivity" unless you explain the mechanism.

## C. How it will work
- How the user interacts with it
- How it interprets requests
- How it gathers information
- How it makes decisions
- How it handles incomplete information
- How it produces results
- How it handles exceptions and complex requests

## D. Research findings
Only what actually influenced the design, with sources. If no research was done, write: "No external research was performed; affected content is marked Assumed."

## E. What I am adding
For every addition beyond the user's input: what it is, why it is useful, and its origin (research, established practice, or own design reasoning).

## F. Proposed architecture
A folder tree containing only files that will exist. One line per file stating its job.

## G. Expected deliverables
Exactly what the user will receive (ZIP, file list, README, licence).

## H. Limitations and dependencies
Platform requirements, tools, integrations, permissions, and features that cannot work without them.

## I. Professional recommendation
Is it worth building? Strongest potential? Recommended approach? If the input holds several capabilities, say whether to split them.

## Closing line (verbatim)
"Would you like me to proceed with this skill architecture, or would you like to modify anything before I build it?"

Then stop and wait.
